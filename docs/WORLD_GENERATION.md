# Admin-reviewed room generation

M5 creates one room and a return connection at a time. Generated content stays
private until its creating admin explicitly approves it. Normal movement never
invokes generation.

## Commands

Sign in as an admin. From Town Square, go `north` to Forest, then:

```text
/world propose north A quiet clearing with mossy stones and the scent of cedar
/world proposals
/world preview <proposal-id>
/world approve <proposal-id>
/world reject <proposal-id>
/world describe Amber light gathers beneath the branches. The air smells of rain and cedar.
```

Copy the full proposal ID from the response. Preview displays the source room,
both planned directions, complete name/description, and status. Approval creates
Forest → north → new room and new room → south → Forest atomically. Other players
in Forest receive an exit notification; anyone can enter and return normally.
Approval does not move anyone automatically.

Reject a pending draft to discard it. Drafts cannot be edited; reject and propose
again. Your latest 20 proposals are listed, and known IDs remain accessible after
reconnect or restart. You can have ten pending drafts. Only the creating account,
while still an admin, can access or decide its drafts. Approval requires returning
to the source room. Repeated approval returns the existing room; it never makes
a second one. Approved rooms cannot be undone through rejection.

Directions accept north/south/east/west/up/down and n/s/e/w/u/d. Existing exits
cannot be replaced. Changed source context, occupied exits, and name conflicts
make proposals stale at approval; request another. Room names must be unique
after trimming and case-folding. IDs and connections are generated by the engine.

`left`, `right`, `forward`, and `backwards` (also `backward`) are relative to the
character's last successful horizontal move. New and migrated characters initially
face north. `look` and movement output show the current facing direction; it
persists across reconnect and restart. Failed moves and up/down leave it unchanged.
For example, after moving east, left means north and right means south. A successful
backwards move from east goes west and changes facing to west, following the last-move
rule. `/world propose` accepts the same relative words but pins the draft's compass
connection at creation; creating a draft does not change facing.

## Edit the current room

`/world describe <description>` replaces the current room's description immediately
for an authenticated admin. Supply the text directly, without surrounding quotes.
It uses the same one-to-five-sentence, 2,000-character validation as generated prose.
The existing command-frame byte limit also applies to manually entered text.
The reply shows the saved description. Nearby players receive a notice and can use
`look` to read it. The change persists across restart and seeding. Changed source
context makes existing drafts stale when approval is attempted.

Editing makes no AI call, consumes no allowance, and works even when generation is
disabled. It changes only the room's description; names, exits, objects, and players
are preserved. It uses the same world-writing lock as approval. Take a backup before
substantial edits; there is no per-room undo or description history in this increment.

## Descriptions and review

Descriptions support up to five sentences and 2,000 characters, shown in full in
preview and room output. Prompts ask for distinctive sensory details, lighting,
texture, sound, scent, and a sense of place while preserving player agency.

Sentence validation follows a deterministic English convention: punctuation runs
of `. ! ?` and supported Unicode equivalents end sentences; closing quotes are
ignored; a trailing fragment counts. Decimal dots, common title abbreviations
(Mr., Mrs., Ms., Dr., St., Prof., Sr., Jr.), and e.g./i.e. are exempt. Unsupported
abbreviations can count as extra sentences. Overlong replies are rejected, never
silently shortened. This is not a general linguistic sentence detector.

Admin review establishes whether the mood and details fit the setting. Structurally
valid prose can still be inaccurate. Ambient scenery does not create usable items,
NPCs, hazards, weather systems, rewards, or additional routes. This increment adds
only one room and two reciprocal exits. The React transcript renders escaped text.

## Configuration and usage

```env
AI_WORLD_GENERATION_ENABLED=true
AI_WORLD_MAX_OUTPUT_TOKENS=1024
```

Generation is off by default. Enable it in ignored local `.env`, pass the deployment
gate, and recreate the backend. It shares `AI_PROVIDER`, explicit model/credentials,
timeout, process attempt/concurrency limits, and account allowance with existing AI.
Real generation remains development-only. Production rejects enabled fake or real
AI providers. The generation output setting leaves interpretation/NPC limits unchanged.
Context is limited to 8,192 UTF-8 bytes, and provider responses to 64 KiB. Invalid
or incomplete replies fail safely, without retry or room creation.

One dispatched generation attempt consumes one AI unit; failed replies count.
Syntax, role, source, pending-cap, and provider-capacity failures before dispatch
are free. Preview/list/approve/reject are free and bypass interpretation/narration.
A response discarded because a concurrent request filled pending capacity still
counts as an attempted generation. With generation disabled, list/preview/reject
remain available, while propose/approve are blocked.

The fake provider returns one five-sentence Mossy Clearing fixture. Once that name
is approved, further fake proposals conflict with it; use isolated worlds for
repeat demos. Real-provider literary quality requires local playtesting.

## Privacy, persistence, and recovery

Only the brief, source name/description, selected outward/return directions, and
fixed instructions go to the provider. No account/character IDs, inventory, NPC
memories, secrets, other drafts, or full map are sent. Text is untrusted data.
The real adapter requests only `name` and `description` using
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
then validates again locally. `store=false` is requested; it does not promise
zero provider retention.

Migration `0011` adds `world_proposals`: creator reference, source fingerprint,
immutable validated prose, schema version, status, timestamps, and result room ID.
The raw brief and raw provider response are not archived. Drafts/decision history
have no automatic expiration. Account deletion clears the creator reference.
Canonical rooms and exits stay in PostgreSQL and survive restart and seeding.
Migration `0012` stores each player's horizontal facing direction, defaulting to north.

Approval locks account, player, proposal, then the transaction-scoped world-writing
advisory lock `50615001`. Future room-editing features must use that lock and
compatible ordering. Provider work holds no database locks. Failed notifications
cannot undo committed geography; `look` or reconnect reads current state. The
existing repository reads room topology per command; revisit all-room reads if
profiling shows world growth makes them expensive.

Take a backup before migrations or substantial expansion. Restoring a backup
restores the whole database, including player progress. See [backup and recovery](BACKUPS.md).
